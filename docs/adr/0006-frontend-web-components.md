# 0006. Frontend: Lit shell and Web Component plugins

- Status: accepted
- Date: 2026-09-29
- Deciders: Massimo Antonini

## Context and problem statement

Third-party plugin frontends must be writable with any technology, load fast and stay
consistent with the theme.

## Decision

- The shell is written with Lit and built with Vite; Quarkus Quinoa serves it and runs Vite in
  development mode.
- A plugin frontend is an ES module whose default export implements `MosaikitPlugin` from
  `@mosaikit/sdk`. Apps are custom elements, so React, Vue, Svelte or Angular can be used.
- The shell passes a context (facade) instead of internal objects.
- Theme tokens are CSS custom properties, which cross the Shadow DOM.
- Untrusted plugins will run in iframes; Piral and the Luigi container are evaluated in the
  prototype before building more of the shell.

## Consequences

- Shared libraries will be provided through an import map generated by the kernel.
- A broken plugin module is reported and skipped; the shell keeps working.
